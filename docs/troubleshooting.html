Troubleshooting & FAQ

Most problems fall into one of the categories below. If you are stuck, open a discussion or an issue and include the output of System information.

Operator and bus

SymptomCause / solution
Operator shows error 04An accessory was added or removed without a bus scan, or the bridge restarted while the operator expected it. Run the bus scan again.
Bus scan does not find the bridge (display 00/01)Check the RJ12 wiring (A/B), the 120 Ω resistor and the RS485 pins under Expert Configuration; swap TX/RX. Make sure the converter switches direction automatically.
Web interface shows No bus / greyed garageNo valid bus communication yet – run the bus scan; check the cable.
No 24 V on the bus (older hardware)Some operators switch off the bus supply when no accessory is registered. Trigger the scan with the DIP switch (ON → OFF); if needed power the bridge temporarily from the operator's 24 V terminal for the scan.
Vent position shown as "stopped"The firmware detects the vent position when the door stops at position 0x08. Other operators may use a different vent position.
Commands are ignoredOnly one command can be pending; send the next one after the door reacted. Stop only works while the door is moving.

Wi-Fi and web interface

SymptomCause / solution
Cannot reach the web interfaceConnect to the hotspot HCPBRIDGE (password gifford47) and open http://192.168.4.1. Disable mobile data / captive-portal checks on the phone.
Hotspot missingThe access point was disabled. Connect via your Wi-Fi, or do a factory reset (5 × boot button).
Drop-outs, slow UICheck the signal in System information: below −80 dBm is too weak. In mesh / multi-AP networks keep Connect to strongest AP enabled.
Wi-Fi does not connectCheck SSID and password (printable ASCII only). 2.4 GHz is required.
Login promptA web password is set: user admin. Forgot it? Factory reset.

MQTT and Home Assistant

SymptomCause / solution
MQTT shows DisconnectedCheck server, port (plain MQTT, default 1883), user and password. Test with mosquitto_sub -h broker -u user -P pass -t 'hormann/#' -v.
No entities in Home AssistantThe MQTT integration must be set up with discovery prefix homeassistant. Discovery is sent once after boot – restart the bridge.
Entities missing or broken topicsThe Device ID must be at most 14 characters.
Duplicate / unavailable entitiesThe Device ID was changed – delete the old entities. With several bridges use unique Device IDs and Device names.
Sensor entity missingThe sensor failed at boot (see sensor_error in the Debug entity) or is not enabled.

Sensors and I/O

SymptomCause / solution
Sensor shown as DisabledNo plausible reading at boot or 5 failed readings in a row. Check wiring and GPIOs, then restart.
All sensors suddenly offThe ESP32 crashed and the crash protection disabled all sensors. Re-enable them one by one to find the culprit.
Parking space always "Free"The reference distance is learned after each restart – if the car was parked during the restart it becomes the reference. Drive out once. See parking detection.
Values update slowlyLower the Sensor query interval or the thresholds.
Input always ON / never changesOn the HCP PCBs the pull mode must be none (external) and Active low off; the input needs ≈5 V. Details: Digital I/O.
io_error in the debug entityThe configured GPIO cannot be used on this chip; the channel was disabled.

Reset button and recovery

The boot button (GPIO 0) counts presses within 6 seconds:

PressesActionLED (HCP v2/v3)
3 ×Disable all sensors and restart – use this when a sensor prevents a normal startblinks 3 times
5 ×Factory reset: erase all settings and restart with the default hotspotrestarts immediately

After a crash (panic or watchdog) the bridge disables all sensors automatically on the next boot.

Serial debugging

  1. Enable Enable serial debug in the basic configuration and save.
  2. Connect USB and open a terminal at 9600 baud (pio device monitor).
  3. The log shows Wi-Fi events, MQTT connection, sensor and I/O initialisation and commands.

FAQ

Does the bridge need internet or a cloud?

No. Everything runs locally; only your MQTT broker and browser talk to it.

Can I still use the original Hörmann remote controls and buttons?

Yes. The bridge is an additional bus accessory; state changes from remotes and buttons are reported to it.

Can one bridge control two doors?

No – one bridge per operator. Several bridges can share one broker; see Several doors.

Is the configuration lost after a firmware update?

No. Settings are stored in NVS and survive OTA updates. Only a factory reset clears them.
